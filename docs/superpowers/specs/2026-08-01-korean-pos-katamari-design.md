# 괴혼 스타일 국어 9품사 학습 게임 — 설계 문서

작성일: 2026-08-01
프로젝트: `27.korean_Gweohon`
상태: 승인됨 (구현 계획 작성 대기)

## 1. 목적과 범위

중학생이 한국어 9품사를 **몸으로 익히도록** 만드는 3D 웹 게임. 『괴혼(塊魂, Katamari Damacy)』의 "공을 굴려 사물을 모아 키운다"를 학습 루프로 옮긴다. 같은 품사끼리 모으는 것이 곧 게임의 승리 조건이다.

이 게임은 국어 학습 종합 플랫폼의 첫 모듈이다. 다만 이 문서의 범위는 **9품사 이해 게임 한 개**로 한정한다. 플랫폼 통합, 교사 대시보드, 학급 데이터 집계는 이 스펙에 포함하지 않는다.

### 1차 버전에서 만들지 않는 것

- 백엔드, 서버, 인증, API 키 — 프론트엔드만으로 완결한다
- 교사 대시보드, Google Sheets 연동, 학급별 성취 집계
- AI 기반 단어 생성 — 고정 사전만 사용한다
- 멀티플레이, 랭킹 서버
- 보스 캐릭터 모델 (보스판은 "섞인 필드 3분"으로만 구현)

## 3. 아키텍처

### 3.1 핵심 원칙 — 게임 규칙은 프레임워크를 모른다

`src/game/` 아래의 모든 코드는 Three.js와 React를 import하지 않는다. 순수 TypeScript 함수와 자료구조만 쓴다. 이렇게 하면 규칙 전체가 Vitest로 검증되고, 버그가 났을 때 "규칙이 틀렸는가, 물리가 틀렸는가"를 즉시 구분할 수 있다.

### 3.3 성능을 지키는 세 가지 규칙

R3F에서 프레임이 떨어지는 원인을 미리 차단한다.

1. **게임 상태를 React state에 두지 않는다.** zustand 스토어에 두고 HUD만 선택적으로 구독한다. 공 위치가 바뀔 때 React가 리렌더되면 안 된다.
2. **프레임마다 바뀌는 값은 `useFrame` 안에서 `ref.current`를 직접 만진다.** 공 위치·회전·지름·카메라가 여기 해당한다.
3. **공에 붙은 사물은 리지드바디를 제거하고 공의 자식 메시로 재부착한다.** 물리 바디 수가 늘지 않으므로 태블릿에서 120개 필드가 유지된다.

### 3.4 입력 추상화

`input/`은 터치 스틱과 키보드를 모두 `{ x: number, y: number }` (각 −1..1, 크기 0..1로 클램프) 하나로 정규화한다. 게임 로직은 입력 장치를 알지 못한다. 조작계를 나중에 바꿔도 게임 코드는 그대로다.

## 4. 게임플레이 규칙

### 4.1 클리어 조건은 지름이 아니라 단어 수

지름을 클리어 조건으로 걸면 "아무거나 붙여 부피만 키우기"가 최적 전략이 되어 학습이 무너진다. 클리어 조건은 **목표 품사 단어 N개 수집**이고, 지름은 그 결과로 커지는 보상 지표다.

### 4.2 성장

- 시작 지름 5cm
- 부착 가능 조건: `objectDiameter <= ballDiameter * 1.1`
- 부착 시 성장: `newD = cbrt(D³ + k · objD³)`, `k = 0.6` (플레이테스트로 조율)
- 90초 안에 클립만 붙던 공이 의자를 삼키는 구간까지 도달한다

`k`는 `growth.ts`에 단일 상수로 두고 테스트에서 경계값을 고정한다.

### 4.3 부착밀 (오답)

목표가 아닌 품사를 붙이면 그 사물은 **부착밀**이 되어 공에 남는다.

- 부착밀 1개당 최대 속도 −12%, 회전 반응 둔화
- 5개 누적 시 과부하 경고: 화면 흔들림 + 대왕 잔소리
- 부착밀도 부피에는 정상 기여한다 (지름은 커진다)

### 4.4 정화 지대 — 학습이 실제로 일어나는 지점

필드에 2~3곳의 발광 링 패드를 둔다. 통과하면 부착밀만 0.25초 간격으로 하나씩 터져 나간다. 터질 때마다:

1. 그 단어의 **정답 품사가 대왕 말풍선으로 0.8초** 표시된다
2. `mistakes.ts`가 오답노트에 기록한다
3. 그 사물의 부피만큼 지름이 줄어든다

버리는 행위가 곧 복습이 되도록 설계했다. 오답을 페널티로만 두면 학생은 오답을 회피하고, 회피하면 배우지 못한다.

### 4.5 시간 압박

90초. 남은 20초부터 BGM 템포가 10% 올라가고 화면 가장자리 비네트가 조인다. 시간 종료 시 목표 미달이면 대왕의 잔소리와 재도전 버튼이 뜬다.

### 4.6 점수와 별

- 기본점 = 정답 단어 수 × 100
- 콤보: 연속 정답 3개마다 배수 +0.2 (최대 2.0). 오답 시 리셋
- 페널티 = 부착밀 발생 수 × 50
- 별 등급 — 조건은 누적이다. 아래 조건을 위에서부터 연속으로 만족한 개수가 별 개수가 된다
  - ★ 목표 달성
  - ★★ 위 + 정확도 85% 이상 (정확도 = 정답 부착 수 / 전체 부착 수)
  - ★★★ 위 + 30초 이상 남기고 달성

### 4.7 난이도 3단 — 색은 비계(scaffold)이지 정답이 아니다

| 단계 | 품사색 | 오답 알림 | 어휘 |
|---|---|---|---|
| 초급 | ON | 붙는 즉시 대왕이 알려줌 | 명확한 기본 어휘 |
| 중급 | ON | 정화 때만 | 기본 어휘 |
| 상급 | **전부 회색** | 정화 때만 | 헷갈리는 어휘 포함 |

상급에서 색을 끄기 때문에 Tripo 모델은 반드시 무채색이어야 한다(§6.2).

### 4.8 모드 4종

**1. 단일 품사 (기본, 9스테이지)** — 목표 품사 하나만 정답. 스테이지 순서는 국어 교과의 품사 분류 순서(체언 → 용언 → 수식언 → 관계언 → 독립언)를 따른다.

| # | 품사 | 목표 개수 | 분류 |
|---|---|---|---|
| 1 | 명사 | 20 | 체언 |
| 2 | 대명사 | 12 | 체언 |
| 3 | 수사 | 12 | 체언 |
| 4 | 동사 | 18 | 용언 |
| 5 | 형용사 | 16 | 용언 |
| 6 | 관형사 | 12 | 수식언 |
| 7 | 부사 | 16 | 수식언 |
| 8 | 조사 | 20 | 관계언 |
| 9 | 감탄사 | 12 | 독립언 |

**2. 멀티 분류** — 화면 하단 품사 칩으로 목표를 전환한다. **붙는 순간의 목표가 정답 기준**이고, 이미 붙은 것은 나중에 목표를 바꿔도 유효하다. 규칙이 한 줄로 끝나고 성장감이 끊기지 않는다. 목표 전환 시 공의 색이 새 목표 품사색으로 바뀐다.

**3. 문장 완성** — 필드에 한 문장의 조각들이 흩어져 있다. 순서대로만 붙을 수 있고, 순서를 틀리면 그 조각은 부착밀이 된다. HUD에 문장의 빈칸 진행이 표시된다.

**4. 왕국 정복 (보스판)** — 오픈 필드가 9품사 구역으로 나뉜다. 제한 시간 3분. 구역별 소목표를 채우면 깃발이 꽂히고, 9구역을 모두 정복하면 클리어.

## 5. 품사 대왕

괴혼의 "왕"에 대응하는 나레이터 캐릭터. 장엄한 척하다 헛소리하는 톤으로 말한다. 이 캐릭터가 게임의 유머와 학습 설명을 동시에 진다.

등장 지점:

- 스테이지 시작 — 목표 훈시
- 부착밀 5개 과부하 — 잔소리
- 정화 순간 — 그 단어의 정답 품사 설명 (0.8초 말풍선)
- 시간 종료·실패 — 잔소리와 재도전 권유
- 클리어 — 평가와 칭찬

대사는 `ui/KingSpeech.tsx`가 렌더하고, 대사 텍스트는 데이터로 분리해 톤을 한곳에서 관리한다.

## 6. 에셋 설계

### 6.1 형태와 품사를 분리한다

단어 오브젝트는 추상 도형이 아니라 **실제 사물**이다. 사물의 형태는 품사와 **무관하게** 랜덤 조합한다. 「학교」가 지우개일 수도, 머그컵일 수도 있다.

두 가지 이유에서다. 첫째, 괴혼의 정체성은 실제 사물이 어이없이 뒤범벅되어 붙는 것이고 추상 도형으로는 그 느낌이 나지 않는다. 둘째, 형태가 품사를 암시하면 학생이 형태로 정답을 찍는 치팅이 가능해진다. 형태와 품사를 분리하면 학생은 **색과 글자만** 보고 판단해야 한다.

### 6.2 색 분업

- **붙는 사물 20종은 Tripo에서 무채색으로 뽑고, 코드에서 품사색을 틴트한다.** 상급 난이도의 회색 통일이 런타임에 가능해야 하기 때문이다. Tripo에서 색을 구워버리면 회색으로 되돌릴 수 없다.
- **카타마리 코어와 품사 대왕은 Tripo에서 풀컬러로 만든다.** 이 둘은 품사색 틴트 대상이 아니다.
- 붙지 않는 전용 배경 프롭도 풀컬러로 만든다. 다만 1차 버전에는 전용 배경 프롭을 두지 않는다(§6.5, §6.7).

### 6.3 크기 티어 20종

괴혼의 스케일 진행을 그대로 쓴다.

| 티어 | 크기 | 사물 |
|---|---|---|
| XS | 1–3cm | 클립, 압정, 단추, 콩자갈, 지우개 조각 |
| S | 4–10cm | 지우개, 연필, 딱풀, 포스트잇 뭉치, 샤프 |
| M | 11–30cm | 필통, 머그컵, 국어사전, 스테이플러, 계산기 |
| L | 31cm–1m | 책가방, 스탠드, 의자, 노트북, 화분 |

공이 5cm일 땐 XS만 붙는다. 1m가 되면 L을 삼킨다.

### 6.4 라벨

한글 단어는 사물의 곡면에 굽지 않는다. 사물에 꽂힌 **작은 이름표 태그**(가격표 형태)로 띄운다. 곡면 왜곡 없이 정면에서 항상 읽히고, 사물다움도 깨지지 않는다.

구현은 `three/labelTexture.ts`가 단어당 256×64 캔버스에 한글을 그려 텍스처로 만들고, 태그 평면 메시에 입힌다. LRU 60개 캐시로 재사용한다. GLB에는 어떤 글자도 넣지 않는다 — 넣으면 단어를 교체할 수 없다.

### 6.5 배경 테마 — 책상 위 세계

괴혼 원작이 방 안에서 시작하는 것과 같은 감성이고, 국어 수업 맥락과도 맞는다. 공이 작을 땐 책상 위 문방구 사이를 굴러다니고, 커지면 책상 자체가 무대가 된다.

바닥·하늘과 정화 지대는 Tripo 없이 셰이더로 만든다. 1차 버전에는 전용 배경 프롭을 만들지 않고, L티어 사물(책가방·스탠드·의자 등)이 배경 역할을 겸한다. 전용 배경 프롭은 P4에서 추가한다.

### 6.6 괴혼 감성을 만드는 요소 — 스펙에 명시한다

- **비주얼**: 플랫 셰이딩, 로우폴리, 아웃라인 없음, 채도 높은 원색, 넓은 하늘, 체크·스트라이프 패턴
- **카메라**: 낮은 각도에서 뒤를 쫓는다. 공이 커지면 거리와 높이가 자동으로 늘어난다
- **지름 표시**: 「32cm 4mm」처럼 밀리미터까지 — 괴혼 특유의 쓸데없이 정밀한 계측
- **부착 감각**: 쫘악 하는 소리 + 사물이 공 표면에 **튀어나온 채로** 함께 회전한다. 공이 매끈해지지 않는 것이 핵심이다
- **종료**: 대왕의 평가와 잔소리

### 6.7 1차 Tripo 제작 목록 — 22개

붙는 사물 20 + 카타마리 코어 1 + 품사 대왕 1.

### 6.8 Tripo 프롬프트 4원칙

붙는 사물 20종에 적용한다.

1. 로우폴리, 플랫 셰이딩에 어울리는 단순 형태
2. 무채색 단색 (색은 코드에서 주입)
3. 엄지손톱 크기로 축소해도 식별되는 단순한 실루엣
4. 얼굴·표정 없음 — 주인공은 이름표다

### 6.9 파이프라인

```
Tripo 웹 (Claude가 열고, 로그인은 사용자가 직접)
  → text-to-3D 생성
  → GLB 다운로드
  → assets/tripo/raw/<name>.glb        원본 영구 보관
  → assets/tripo/manifest.json         프롬프트·생성일·출처 기록
  → gltf-transform (prune + draco + 텍스처 리사이즈)
  → public/models/<name>.glb           게임이 읽는 것
```

`manifest.json`에 프롬프트를 반드시 남긴다. 마스콧 하나를 다시 뽑아야 할 때 같은 톤으로 재생성할 수 있어야 한다.

## 7. 데이터 모델

### 7.1 words.json

품사별 배열이 아니라 flat 배열로 둔다. 필터·샘플링·티어 배정이 단순해진다.

```json
{
  "version": 1,
  "words": [
    { "text": "학교", "pos": "명사", "syllables": 2 },
    { "text": "달리다", "pos": "동사", "syllables": 3 }
  ]
}
```

유일성은 `text` + `pos` 조합으로 판정한다. 동형이의어(예: 「하나」가 수사이기도 하고 명사이기도 한 경우)는 서로 다른 항목으로 공존할 수 있으나, **같은 스테이지에 함께 스폰되지 않도록** 스포너가 배제한다. 판정 불가능한 오브젝트를 필드에 두면 안 된다.

### 7.2 어휘 큐레이션 원칙

중1 수준에서 품사가 명확히 갈리는 것만 넣는다.

- 용언은 **기본형**으로 표기한다 (달리다, 아름답다). 활용형은 품사 판정이 흐려지므로 쓰지 않는다
- 서술격 조사 「이다」는 제외한다
- 조사는 대표적인 격조사와 보조사만 넣는다 (은, 는, 이, 가, 을, 를, 에, 도, 만 등)
- 접속부사는 제외한다
- 품사별 최소 40개를 확보한다 (9품사 × 40 = 약 360개). 스테이지 목표가 최대 20개이므로 매번 다른 조합이 나온다

### 7.3 localStorage

최상위에 `version`을 둬서 스키마가 바뀌어도 학생 기록이 날아가지 않게 한다.

```
키: gweohon:v1

{
  version: 1,
  progress: {
    "singlePos:명사": { cleared: true, stars: 2, bestScore: 2400, bestDiameterMm: 842 }
  },
  mistakes: [
    { text: "매우", pos: "부사", count: 3, lastAt: 1780000000000 }
  ],
  settings: { difficulty: "basic", bgmVolume: 0.7, sfxVolume: 0.9, stickSide: "right" }
}
```

`persist/`가 읽을 때 `version`을 확인하고, 낮으면 마이그레이션 함수를 순차 적용한다. 파싱 실패 시에는 기록을 버리고 초기 상태로 시작한다(게임이 뜨지 않는 것보다 낫다).

## 8. 조작

### 8.1 터치 (주 플랫폼)

화면 오른쪽 절반 어디든 처음 닿은 지점이 스틱 중심이 되는 **플로팅 가상 스틱**. 고정 위치 스틱보다 손 크기와 기기 크기 차이를 잘 흡수한다. 반경 60px, 중심에서 벗어난 방향과 거리가 입력 벡터가 된다.

`settings.stickSide`로 왼손잡이가 왼쪽 절반으로 바꿀 수 있다.

### 8.2 PC

방향키 또는 WASD가 같은 입력 벡터를 만든다. 마우스 좌우 드래그로 카메라를 돌린다.

### 8.3 공의 반응

입력 벡터를 공에 토크·임펄스로 적용한다. 부착밀이 있으면 최대 속도가 깎인다(§4.3). 카메라는 감쇠(damping)를 걸어 부드럽게 뒤를 따르고, 지름이 커지면 거리와 높이가 함께 늘어난다.

## 9. 화면 흐름

```
타이틀
  → 모드 선택 (단일 품사 / 멀티 분류 / 문장 완성 / 왕국 정복)
  → 난이도 선택 (초급 / 중급 / 상급)
  → 스테이지 선택 (9 + 보스판, 진행도에 따라 해금)
  → 플레이 (HUD: 남은 시간 · 목표 품사 · 수집 N/M · 지름 · 부착밀 개수)
  → 결과 (대왕 평가 · 별 · 점수 · 헷갈린 단어 목록 · 다시하기)
  → 오답노트 (누적된 헷갈린 단어를 품사별로 열람)
```

오답노트는 타이틀에서도 직접 들어갈 수 있다.

## 10. 검증

### 10.1 Vitest 자동 테스트 — `src/game/`과 `src/persist/` 전면

- `growth.ts` — 부착 판정 경계값(1.1배 직전/직후), 부피 합산 정확도, 정화 시 지름 감소
- `scoring.ts` — 콤보 증가와 리셋, 배수 상한 2.0, 페널티, 별 등급 경계
- `words.ts` — 티어 분포, 목표 품사와 오답 품사의 비율, 중복 없음, 동형이의어 동시 스폰 배제
- `modes/*` — 4개 모드의 정답 판정과 클리어 판정. 문장 완성의 순서 위반 판정
- `mistakes.ts` — 같은 단어 반복 시 count 증가, 정렬
- `persist/` — v1 읽기·쓰기, 손상된 JSON에서 초기 상태 복구, 버전 마이그레이션

### 10.2 자동 테스트하지 않는 것

물리 거동과 렌더링은 자동 테스트 대상이 아니다. 수동 QA 체크리스트와 `/browse` 스모크 테스트로 확인한다.

수동 QA 체크리스트에 반드시 포함할 항목:

- 태블릿 실기기에서 플로팅 스틱이 의도대로 잡히는가
- 공이 커질 때 카메라가 사물을 가리지 않는가
- 이름표가 공에 붙은 뒤에도 읽히는가
- 상급 난이도에서 색이 완전히 제거되는가
- 부착밀 5개 상태에서 정화 지대까지 갈 수 있는가 (밸런스)

## 11. 구현 순서

수직 슬라이스부터 간다.

| Phase | 내용 |
|---|---|
| **P1** | 단일 품사 모드 · 명사 스테이지 1개 · 사물 5종 · 코어 1개. 조작·물리·성장·라벨을 실제로 굴려보며 검증 |
| **P2** | 9스테이지 전체 · 정화 지대 · 품사 대왕 · 결과 화면 · 오답노트 · localStorage |
| **P3** | 멀티 분류 · 문장 완성 모드 · 난이도 3단 · 사운드 |
| **P4** | 왕국 정복(보스판) · 폴리시 · 성능 튜닝 |

**P1이 이 프로젝트의 성패를 가른다.** "공을 굴리는 것이 실제로 재미있는가"는 코드를 굴려보기 전에는 알 수 없고, 재미없다면 나머지를 다 만들어도 소용없다. P1에 필요한 Tripo 에셋은 사물 5종 + 코어 1개뿐이므로, 22개를 다 만들기 전에 검증이 끝난다.

P1에서 재미가 나오지 않으면 물리 파라미터(`k`, 토크 세기, 카메라 감쇠)를 먼저 조율하고, 그래도 안 되면 조작계 결정을 재검토한다.
